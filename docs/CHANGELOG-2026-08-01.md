## 4. ความปลอดภัย

### 4.1 LINE webhook ไม่เช็คลายเซ็น — `3cb1000` 🔴

`/api/line/webhook` เป็น URL สาธารณะที่**ถอนชื่อคนได้** ใครรู้ URL ยิง JSON ปลอมก็ถอนใครออกจากวันไหนก็ได้ ไม่ต้องอยู่ในกลุ่ม ไม่ต้องมี token

ตรวจ `X-Line-Signature` = base64 ของ HMAC-SHA256 บน raw body ด้วย channel secret (WebCrypto แบบเดียวกับ `lib/adminCookie.ts`)

⚠️ **ต้องอ่าน `req.text()` แล้ว `JSON.parse` เอง** ลายเซ็นครอบ byte ชุดนั้นเป๊ะ ถ้าใช้ `req.json()` แล้ว serialize กลับ byte เปลี่ยน ลายเซ็นไม่มีทางตรง

ตอนนั้นยังไม่ได้ตั้ง secret และ fail-closed จะทำให้บอทตายทันที เลยกันเฉพาะตัวที่อันตราย: ไม่มี secret → ถอนชื่อถูกปฏิเสธ ตอบรายชื่อได้ปกติ

**พิสูจน์แล้ว** ยิง curl ปลอมสั่งถอน BB → BB ยังอยู่ครบทั้งสองวัน ก่อนแก้คำสั่งนี้ถอนได้จริง

### 4.2 แผงบอก env ที่ขาด — `aeade89`

ทุกตัวพังเงียบ: ไม่มี `CRON_SECRET` = cron endpoint เปิด, ไม่มี `ADMIN_SECRET` = คุกกี้แอดมินเซ็นด้วย PIN, ไม่มี `LINE_CHANNEL_SECRET` = ตรวจลายเซ็นไม่ได้ — แอปทำงานได้หมด เลยไม่มีอะไรบอก

หน้าแอดมินขึ้นเฉพาะตัวที่ขาด พร้อมบอกว่าขาดแล้วเสียอะไร ครบแล้วไม่ขึ้นเลย

อ่านแค่ว่า**ตั้งรึยัง** ไม่เคยอ่านค่า (มีเทสต์ยืนยัน) · ค่าที่เป็นช่องว่างล้วนนับว่ายังไม่ตั้ง

## 7. บทเรียนที่ควรจำ

**อย่าแก้ schema บน production ด้วย `ALTER TABLE` ตรงๆ** มันได้ผลทันที แล้วไฟล์ schema / migration / DB ก็พูดคนละเรื่องกัน — ที่เจอทั้ง 3 จุดในข้อ 5.1 มาจากทางนี้หมด

**เปลี่ยนกฎแล้วต้องแก้เทสต์และคอมเมนต์** ที่เจอในข้อ 5.2 กับ 5.3 คือกฎเปลี่ยนแต่รอบข้างไม่ตาม เทสต์ที่แดงค้างนานๆ ทำให้ทั้งชุดเทสต์เชื่อไม่ได้

**เตือนที่จุดที่คนตัดสินใจ ไม่ใช่ในเอกสาร** เรื่องปิดเควสแล้วจ่ายซ้ำเขียนไว้ใน `GAMIFICATION.md` แล้ว แต่คนที่กำลังกดปุ่มไม่ได้เปิดอ่าน — ป้ายบนปุ่มกับคำเตือนในฟอร์มถึงจะช่วยได้จริง

**เช็คว่า deploy ขึ้นแล้วก่อนแตะ DB** ตอนเปลี่ยน August Bonus เป็นกฎรายวัน ถ้า production ยังรันโค้ดเก่า กฎใหม่จะกลายเป็นกฎที่ระบบไม่รู้จัก EXP เป็น 0 ทั้งก๊วนทันที — วิธีที่ใช้คือจดค่าก่อน แก้ แล้วรีเฟรชเช็คซ้ำ ผิดเมื่อไหร่ย้อนได้ทันที

**เทสต์ที่ตอบคำถามผิดข้อ** เทสต์ "พิมพ์ `รายชื่อ` แล้วบอทตอบ = secret ถูก" ที่ให้ไปตอนแรกใช้ไม่ได้ เพราะไม่มี secret บอทก็ตอบเหมือนกัน — แยกได้แค่ "secret ผิด" ไม่ได้แยก "ยังไม่ได้ตั้ง" ต้องดูแผง env ถึงจะชี้ขาด

**จาก `PERF-AUDIT.md`** `MultiSignUpForm.tsx` กับ `SignUpForm.tsx` แชร์บล็อกค้นหาผู้เล่นแบบ debounce รวมเป็น hook เดียวได้ — ปล่อยไว้เพราะเป็นฟอร์มที่ผู้เล่นใช้ทุกวัน ความเสี่ยงไม่คุ้ม

## 9. กฎที่ต้องรักษาไว้

- **แตะ EXP ของเหรียญหรือเควสเมื่อไหร่ ต้องเช็คเส้นแบ่งเลเวล 2 ใหม่ทุกครั้ง** — คนมาวันเดียวต้องไม่ถึง Lv.2 และคนมาสองวันต้องไม่ค้าง Lv.1 (เคยพลาดมาแล้ว เหรียญดัน 8 คนข้ามเลเวล)
- **ห้ามเขียนข้อมูลทดสอบลง production DB ระหว่างมีเกม** และถ้าสร้างอะไรไว้ทดสอบต้องลบให้หมด
- **รัน `prisma migrate deploy` เองก่อน deploy โค้ดที่ใช้คอลัมน์ใหม่** Vercel ไม่รันให้
- **ถอนชื่อต้องผูกกับเครื่อง** การเลือกชื่อจากลิสต์ต้องไม่กลายเป็นปุ่มสั่งการ
